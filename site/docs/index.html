1. Quick Start & Setup

TZ AI DEBLOATER TOOL interfaces with Android devices via the official Android Debug Bridge (ADB). Root access is not required; non-root debugging operates safely within user-space boundaries.

Enabling USB Debugging on Android

  1. Open Settings → About phone on your device.
  2. Tap Build number (or OS version) 7 times until Developer options are unlocked.
  3. Navigate to Settings → System (or Additional Settings) → Developer options.
  4. Enable USB debugging.
  5. Xiaomi / POCO devices: Also enable USB debugging (Security settings) if prompted to grant permission modification.
  6. Connect the phone to your PC with a data-capable USB cable and accept the RSA prompt: "Always allow from this computer".

Wireless ADB Setup (Android 11+)

If your phone and PC share the same Wi-Fi network, you can connect wirelessly without a cable:

  1. In Developer options, enable Wireless debugging.
  2. Tap Pair device with pairing code to reveal the IP address, pairing port, and 6-digit code.
  3. In the desktop tool's Devices screen, click Wireless ADB Setup, enter the details, and click Pair Device.

2. Multi-User Profile Isolation

Modern Android versions isolate application states per user ID:

  • User 0: Primary Owner profile.
  • User 10 / 11: Managed Work Profile (Android Enterprise).
  • User 999: Dual Apps / Parallel Spaces on Xiaomi, Samsung, and OnePlus.

Executing an uninstall command without user specification can inadvertently alter unintended profiles. TZ AI DEBLOATER TOOL queries pm list users, displays active profiles in the top target strip, and appends explicit --user <id> flags to all commands.

3. Package Classification Dimensions

Unlike tools that conflate catalog tags with safety status, TZ AI DEBLOATER TOOL tracks three distinct dimensions:

Dimension Possible Values Source of Truth Implication
Android Package Type System, UpdatedSystem, User Android pm list packages -s -f metadata Identifies whether the APK lives in /system/app or /data/app.
Catalog Rating Recommended, Advanced, Expert, Unsafe, Unlisted Curated debloating community database Descriptive community experience. Never overrides hardware protection rules.
Removal Eligibility Eligible, ReviewOnly, Protected, AlreadyRemoved Safety Policy engine evaluation Enforces whether batch actions or AI automated plans are permitted to touch the package.

4. Hardware & Vendor Safeguards

To prevent device soft-bricks and bootloops, the backend safety engine blocks critical services:

  • MediaTek & Modem Services: com.mediatek.telephony, com.mediatek.ims, com.mediatek.wfo.impl are permanently locked as Protected.
  • Active Launcher & IME: The currently active home launcher and default software keyboard are protected from removal.
  • Built-in ROM Utilities: Built-in calculators, notes, compasses, and screen recorders (e.g. com.miui.compass, com.sec.android.app.popupcalculator) are marked Review-Only and excluded from automated debloating batches.

5. AI Assistant & Gemini Integration

The AI Assistant proposes personalized debloating plans tailored to your device model and storage goals.

Gemini Direct Setup

Obtain a free Google AI Studio API key at aistudio.google.com. In Settings → AI Connections, select Gemini Direct, paste your API key, and select gemini-2.5-flash. Credentials are saved directly into the Windows Credential Manager.

Consent Boundary: Zero device metadata is transmitted until you check the explicit AI Consent checkbox. Package lists are sanitized before prompt formulation.

6. Journal & Rollback Recovery

Every operation performed in the tool is recorded in an encrypted SQLite database on your local disk (journal.db).

Action Taken Underlying ADB Command Recovery ADB Command
Disable pm disable-user --user <id> <package> pm enable --user <id> <package>
Uninstall (User) pm uninstall -k --user <id> <package> cmd package install-existing --user <id> <package>

To restore an uninstalled package, visit Journal & Recovery, click on the historical operation, and select Restore Package.

8. Troubleshooting & Common Error Codes

SecurityException / Permission Denial

On Xiaomi / POCO devices, disabling system daemons requires enabling "USB debugging (Security settings)" in Developer options. This setting requires a Xiaomi SIM card during toggle.

Failure [DELETE_FAILED_INTERNAL_ERROR]

The package is hard-pinned into the ROM read-only image or owned by device policy controller (Knox / Enterprise MDM). Use Disable instead of Uninstall.

Device Unauthorized

Unlock your phone screen, check the USB cable connection, and accept the RSA host authorization dialog.

Wireless ADB Offline

Android changes wireless debugging ports on each reconnect. Re-check the current port displayed under Wireless Debugging in Developer Options.
